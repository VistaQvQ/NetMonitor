## 二、GIF 动画素材处理（enjoywork.gif v1→v7）

### 2.1 目标与约束

把「摸鱼.gif」（111×81、91 帧、黑线白底）处理成 NetMonitor 悬浮窗可用的动画：**56×56 方形画布、透明背景 + 黑白线条、单色（透明/黑/白）、速度统一**。

### 2.2 核心算法链路

```
源 GIF (111×81×91帧)
  → 全帧联合 bbox 裁剪（去空白）
  → 洪泛填充判「外部」/「内部」
       · 播种点：仅顶行 + 左右列（排除底行，防裁切边泄漏）
       · 线条掩膜膨胀 1px 闭合成环，防开环泄漏
  → 外部置透明、内部按亮度 160 二值化
  → BOX 区域平均降采样至 56×44
  → 底部对齐放入 56×56 方形画布
```

### 2.3 各版本迭代与关键技术点

| 版本 | 需求 | 根因 / 方案 | 关键结果 |
|---|---|---|---|
| **v1** | 基础规格化 | bbox 裁剪 + 洪泛填充 + 二值化 + 降采样 | 全 91 帧仅 透明/黑/白 |
| **v2** | 去外圈白 + 统一速度 | 膨胀 1px 把抗锯齿灰环误判为内部白；改「取消膨胀 + 4 连通填充 + 8 连通剥离外圈白」 | 外圈白 ~108px/帧 → 91 帧合计仅 5px；duration 统一 30ms |
| **v3→v4** | 居中放大 + 60ms | 最宽帧约束裁剪窗 (15,7,102,81)；膨胀 1px 闭合「口袋」缺口 + 播种加底行填口袋 + 单步晕环吸收 | 56×48 垂直居中；外圈白残留 0px |
| **v5** | 口袋白色回填 | 用户确认口袋应为白色（非背景）；改回 v3 填充逻辑 + 去目标分辨率安全剥离 | 口袋 y=49-51 白色实心 |
| **v6** | 三边白边清除 | BOX 降采样把边缘白渗出（V 值图外部默认 255）；改「值图外部置 0 + 方向性剥离」 | 上/左/右白边 3574→0，口袋保留 261px |
| **v7** | 删左顾右盼 + 重居中放大 | diff(i,i+11)=0 严格 11 帧周期，保留 5 完整周期（55 帧） | 55 帧 × 60ms，循环无缝，线性放大 14.5% |

### 2.4 经验教训

1. **洪泛填充的「内部白」不一定是背景**——贴画布裁切边的封闭区域语义需用户确认，不应自行判定为透明。
2. **GIF 缩小时细线易被区域平均抹掉**——需让「墨色」在边缘优先（值图外部置 0）+ 方向性边界清理。
3. **膨胀闭合缺口有副作用**——1px 膨胀会把紧贴黑线的抗锯齿灰环误判为内部，需「单步晕环吸收」抵消。

## 三、悬浮窗 DPI 变形修复（→ 最终固定尺寸不缩放）

### 3.1 根因链

```
app.manifest 声明 PerMonitorV2
   ↓ 但 csproj 用 <None Include="app.manifest" />（不是 <ApplicationManifest>）
   ↓ manifest 从未嵌入 exe
   ↓ 进程一直以 DPI Unaware 运行
   ↓ Windows 对 per-pixel alpha 分层窗口做位图缩放虚拟化
   ↓ 逻辑坐标与物理像素错位 → 高 DPI 屏「变形」
```

关键证据：csproj 第 164 行 `<None Include="app.manifest" />`，无 `<ApplicationManifest>` 属性。

### 3.2 修复过程（两轮）

**第一轮：让 manifest 生效 + 手动 DPI 缩放**（后被需求变更推翻）
- `csproj`：加 `<ApplicationManifest>app.manifest</ApplicationManifest>`
- `NetMonitor.cs`：加 `dpiScale` 字段 + `OnDpiChanged` + 渲染管线统一缩放

**第二轮：改为「任何情况都不缩放」**（最终方案）
- 需求明确：窗体在任何 DPI 下保持 **193×56 物理像素**，不放大不模糊
- 撤销全部 `dpiScale` 缩放逻辑，渲染恢复固定像素
- 保留 `AutoScaleMode = None`

### 3.3 最终方案

| 层 | 做法 | 效果 |
|---|---|---|
| manifest | `PerMonitorV2`（进程 DPI 感知） | Windows **不做位图缩放**（清晰） |
| 代码 | 固定 193×56，不缩放 | 任何 DPI 下尺寸一致 |
| AutoScale | `None` | 禁用 WinForms 自动缩放 |

**最终 manifest（微软标准写法）**：

```xml
<application xmlns="urn:schemas-microsoft-com:asm.v3">
  <windowsSettings>
    <dpiAware xmlns="http://schemas.microsoft.com/SMI/2005/WindowsSettings">true</dpiAware>
    <dpiAwareness xmlns="http://schemas.microsoft.com/SMI/2016/WindowsSettings">PerMonitorV2</dpiAwareness>
  </windowsSettings>
</application>
```

## 四、SxS「并行配置不正确」启动报错

### 4.1 根因

第一轮重写的 manifest 用了**两个 `<application>` 节点**，且 `<dpiAware>`/`<dpiAwareness>` 未用 SMI 命名空间：

```xml
<!-- 错误写法：两个 application 节点 + 命名空间缺失 -->
<application xmlns="urn:schemas-microsoft-com:asm.v3">
  <windowsSettings><dpiAware>true</dpiAware></windowsSettings>
</application>
<asmv3:application xmlns:asmv3="...">
  <asmv3:windowsSettings><dpiAwareness>PerMonitorV2</dpiAwareness></asmv3:windowsSettings>
</asmv3:application>
```

manifest 嵌入 exe 后，SxS 解析失败 → 启动报错「应用程序的并行配置不正确」。

### 4.2 修复

重写为**单个** `<application>` 节点 + 正确的 SMI 命名空间（见 3.3），并验证：application 节点数 = 1、`dpiAware` 用 `SMI/2005`、`dpiAwareness` 用 `SMI/2016`。
