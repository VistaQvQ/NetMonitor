## 二、背景：为什么必须重构透明机制

项目原先用 WinForms 的 **`TransparencyKey` 色键透明**：把窗体中"精确等于某颜色（`SystemColors.Control`，浅灰白 240,240,240）"的像素抠成透明。

色键是**二值透明**——像素要么完全透明、要么完全不透明，没有中间 alpha。由此产生一个不可调和的矛盾：

| 诉求 | 色键下的结果 |
|---|---|
| 描边丝滑（抗锯齿） | 抗锯齿会在"图形 → 透明"边界产生过渡像素，过渡终点是色键色（浅灰白），在深色桌面上表现为**一圈 1px 白边** |
| 无白边 | 只能关闭抗锯齿，回到**像素台阶锯齿** |
| 半透明 | 完全无法实现 |

**结论**：色键机制下「丝滑 / 无白边 / 半透明」三者不可兼得。三者的唯一交汇点是 **Per-Pixel Alpha（逐像素 alpha 分层窗口）**，即本次重构的目标。

## 三、核心技术：Per-Pixel Alpha 渲染

### 3.1 原理对比

| 机制 | 底层实现 | 半透明 | 边缘质量 | 透明区穿透 |
|---|---|:---:|---|:---:|
| **色键（重构前）** | `TransparencyKey` = `WS_EX_LAYERED` + `SetLayeredWindowAttributes(LWA_COLORKEY)` | ❌ 二值 | 抗锯齿→白边 | ✅ 自动 |
| **逐像素 alpha（重构后）** | `WS_EX_LAYERED` + `UpdateLayeredWindow`（32bpp ARGB） | ✅ 每像素 | 平滑无杂边 | ✅ α=0 自动穿透 |

核心差异：色键是"抠掉某个颜色"，逐像素 alpha 是"每个像素自带 alpha 通道，由系统按 alpha 混合"。后者让半透明、抗锯齿边缘、透明穿透全部成为**系统原生行为**。

### 3.2 新增 P/Invoke（`NativeApi.cs`）

分层窗口渲染需要 user32 的 `UpdateLayeredWindow` + gdi32 的兼容 DC 系列函数：

```csharp
// ── 常量 ──
internal const int  ULW_ALPHA      = 0x00000002;
internal const byte AC_SRC_OVER    = 0x00;
internal const byte AC_SRC_ALPHA   = 0x01;   // 位图带 Alpha 通道，按像素混合

// ── 结构体 ──
[StructLayout(LayoutKind.Sequential)] internal struct POINT { public int X, Y; }
[StructLayout(LayoutKind.Sequential)] internal struct SIZE  { public int cx, cy; }
[StructLayout(LayoutKind.Sequential)]
internal struct BLENDFUNCTION {
    public byte BlendOp, BlendFlags, SourceConstantAlpha, AlphaFormat;
}

// ── user32 ──
[DllImport("user32.dll", SetLastError = true)]
internal static extern bool UpdateLayeredWindow(
    IntPtr hwnd, IntPtr hdcDst, ref POINT pptDst, ref SIZE psize,
    IntPtr hdcSrc, ref POINT pptSrc, int crKey, ref BLENDFUNCTION pblend, int dwFlags);
[DllImport("user32.dll")] internal static extern IntPtr GetDC(IntPtr hWnd);
[DllImport("user32.dll")] internal static extern int ReleaseDC(IntPtr hWnd, IntPtr hDC);

// ── gdi32（位图 → 兼容 DC） ──
[DllImport("gdi32.dll")] internal static extern IntPtr CreateCompatibleDC(IntPtr hdc);
[DllImport("gdi32.dll")] internal static extern IntPtr SelectObject(IntPtr hdc, IntPtr hObject);
[DllImport("gdi32.dll")] internal static extern bool DeleteObject(IntPtr hObject);
[DllImport("gdi32.dll")] internal static extern bool DeleteDC(IntPtr hdc);
```

### 3.4 渲染管线（`RenderFrame`）

由 `gifTimer`（16ms）统一驱动，每帧把「GIF 帧 + 玻璃胶囊 + 文字」合成到一张 32bpp ARGB 位图，再整体交给 `UpdateLayeredWindow` 呈现：

```
RenderFrame()
  ├─ 复用 renderBitmap（尺寸不变不重建，避免每帧分配内存）
  ├─ Graphics.FromImage(renderBitmap)
  │    ├─ g.Clear(Color.Transparent)      ← 全透明起步
  │    ├─ DrawGifFrame(g)                 ← 左侧 GIF 动画（透明区 α=0）
  │    ├─ DrawGlassCapsule(g)             ← 右侧纯白胶囊 + 纯黑描边（抗锯齿）
  │    └─ DrawText(g)                     ← 文字（ClearType）
  └─ PresentLayered(renderBitmap)
```

关键代码：

```csharp
private void RenderFrame()
{
    if (!this.IsHandleCreated || this.IsDisposed) return;

    int w = this.ClientSize.Width, h = this.ClientSize.Height;
    if (w <= 0 || h <= 0) return;

    if (renderBitmap == null || renderBitmap.Width != w || renderBitmap.Height != h)
    {
        if (renderBitmap != null) renderBitmap.Dispose();
        renderBitmap = new Bitmap(w, h, PixelFormat.Format32bppArgb);
    }

    using (var g = Graphics.FromImage(renderBitmap))
    {
        g.Clear(Color.Transparent);
        DrawGifFrame(g);
        DrawGlassCapsule(g);
        DrawText(g);
    }

    PresentLayered(renderBitmap);
}
```

### 3.5 呈现：premultiplied alpha（`PresentLayered`）

```csharp
private void PresentLayered(Bitmap bmp)
{
    IntPtr hdcScreen = NativeApi.GetDC(IntPtr.Zero);
    IntPtr hdcMem    = NativeApi.CreateCompatibleDC(hdcScreen);
    IntPtr hBitmap   = bmp.GetHbitmap(Color.FromArgb(0));   // 转 premultiplied alpha
    IntPtr hOld      = NativeApi.SelectObject(hdcMem, hBitmap);

    try
    {
        var size  = new NativeApi.SIZE  { cx = bmp.Width, cy = bmp.Height };
        var ptSrc = new NativeApi.POINT { X = 0, Y = 0 };
        var ptDst = new NativeApi.POINT { X = this.Left, Y = this.Top };
        var blend = new NativeApi.BLENDFUNCTION {
            BlendOp = NativeApi.AC_SRC_OVER, BlendFlags = 0,
            SourceConstantAlpha = 255, AlphaFormat = NativeApi.AC_SRC_ALPHA
        };

        NativeApi.UpdateLayeredWindow(
            this.Handle, hdcScreen, ref ptDst, ref size,
            hdcMem, ref ptSrc, 0, ref blend, NativeApi.ULW_ALPHA);
    }
    finally
    {
        NativeApi.SelectObject(hdcMem, hOld);
        NativeApi.DeleteObject(hBitmap);
        NativeApi.DeleteDC(hdcMem);
        NativeApi.ReleaseDC(IntPtr.Zero, hdcScreen);
    }
}
```

**premultiplied alpha 要点**：`Bitmap.GetHbitmap(Color.FromArgb(0))` 会把 ARGB 位图转换成 **premultiplied alpha** 格式的 HBITMAP，与 `AC_SRC_ALPHA` 混合标志配套使用。这是 `UpdateLayeredWindow` 正确呈现半透明边缘的关键，否则边缘会出现黑色/白色晕染。

### 3.6 关键设计点

1. **透明区自动穿透**：alpha=0 的像素由系统命中测试（`WM_NCHITTEST`）逐像素判定为"点不到窗体"，鼠标穿透是**内置行为**——无需 `WS_EX_TRANSPARENT`、无需 `Region`，从根上杜绝了"透明区不可选中/拦截鼠标"的问题。
2. **子控件退居数据源**：`panel.Visible = false`，Label/PictureBox 不再自动渲染，只提供 `Text/Font/ForeColor/Location` 供 `DrawString` 复用，保证与原有布局完全一致。
3. **胶囊恢复抗锯齿**：分层窗口下边缘 alpha 渐变是"正确"的抗锯齿（α 渐变而非颜色渐变），黑描边外是"黑→透明"的干净过渡，白边与锯齿同时消失。
4. **画布复用**：`renderBitmap` 尺寸不变时复用，避免每帧 `new Bitmap` 造成的 GC 压力。

## 四、文字渲染：颗粒感 → ClearType

### 4.1 根因

重构初期文字用 `TextRenderingHint.AntiAliasGridFit`（**灰度抗锯齿**）。灰度 AA 在 10.5pt 楷体 Bold 这类细笔画字体上，笔画边缘被"打点"糊成颗粒感。而原版文字由 Label 控件渲染，默认用的是 **ClearType 子像素抗锯齿**（平滑得多），重构后产生了质量回退。

### 4.2 修复

```csharp
private void DrawText(Graphics g)
{
    g.TextRenderingHint = TextRenderingHint.ClearTypeGridFit;   // 原 AntiAliasGridFit
    DrawLabel(g, labelup);
    DrawLabel(g, Lable_SpeedUP);
    DrawLabel(g, labeldwon);
    DrawLabel(g, Lable_SpeedDown);
}
```

### 4.3 为什么这里能安全用 ClearType

ClearType 在**透明背景**上会产生彩色杂边（子像素 RGB 条纹），这是之前选灰度 AA 的原因。但本项目文字**全部落在不透明的白色胶囊内**（Label 起点 x=71，胶囊左缘 x=61，文字不越过胶囊边界到透明区），ClearType 以白色为底正确渲染，不产生杂边。

## 五、鼠标交互变化

重构前右键菜单由子控件的 `ContextMenuStrip` 自动触发；分层窗口下子控件不渲染，改为窗体级手动处理：

```csharp
private void NetMonitor_MouseDown(object sender, MouseEventArgs e)
{
    if (e.Button == MouseButtons.Left)
    {
        // 无边框窗体拖动
        NativeApi.ReleaseCapture();
        NativeApi.SendMessage(this.Handle, NativeApi.WM_SYSCOMMAND,
            NativeApi.SC_MOVE + NativeApi.HTCAPTION, 0);
        WriteUserSettings();
    }
    else if (e.Button == MouseButtons.Right)
    {
        Menu.Show(this, e.Location);   // 手动弹出右键菜单
    }
}
```

## 六、遗留注意事项

1. **拖动待实测**：SC_MOVE 对分层窗口理论上正常（每帧 `PresentLayered` 用 `this.Left/Top` 自纠正位置），若实测拖影/不跟手，改手动拖动（MouseDown 记录 + MouseMove 更新 Location + 鼠标 Capture）。
2. **文字像素级偏差**：`DrawString` 与 Label 控件渲染可能有 1px 级位置偏差，若文字未居中需微调 `Location`。
3. **GDI 资源**：`PresentLayered` 每次创建/销毁 HBITMAP 与 DC 并正确还原（`SelectObject` 旧对象 + `DeleteObject/DeleteDC/ReleaseDC`），无泄漏。
