## 二、GIF 动画帧率控制重构

### 2.1 背景：跳帧导致不丝滑

原实现用 `WinForms.Timer(16ms)` 固定 Tick + 跳帧：

```csharp
gifFrameIndex = (gifFrameIndex + gifStep) % gifFrameCount;  // gifStep=1/2/3 跳帧
```

`Catdog` GIF 共 **47 帧**（56×56）。`gifStep=2/3` 时帧序列变成 `0,3,6,9…`，47 不能被 2/3 整除 → 帧序列错位、抖动，这是"不丝滑"的根因。

### 2.2 方案：不跳帧，改为按帧率控制

`gifStep` 语义从「跳帧数」改为「帧率档位」，每次只推进 1 帧（连续播放），通过调整渲染帧率来控制动画快慢。

**关键障碍**：`WinForms.Timer` 基于 `WM_TIMER` 消息，精度约 15.6ms，根本无法达到 80/100fps 需要的 12.5/10ms 间隔。

### 2.3 高精度定时：`timeBeginPeriod`

```csharp
[DllImport("winmm.dll")]
internal static extern uint timeBeginPeriod(uint uMilliseconds);
[DllImport("winmm.dll")]
internal static extern uint timeEndPeriod(uint uMilliseconds);
```

`SetGifBackground` 里 `timeBeginPeriod(1)` 把系统定时器分辨率从 15.6ms 提升到 1ms；`FormClosing` 里 `timeEndPeriod(1)` 成对还原。

### 2.4 心跳 + Stopwatch 累积调度

`gifTimer` 从 `WinForms.Timer` 换成 `System.Timers.Timer`（线程池定时器，配合 timeBeginPeriod 可达 ms 级）：

```csharp
// 字段
private System.Timers.Timer gifTimer;
private System.Diagnostics.Stopwatch gifSw;
private double gifAccumMs = 0;
private double gifFrameIntervalMs = 1000.0 / 60;   // 目标帧间隔，随档位变化

// SetGifBackground 里：5ms 心跳
gifTimer = new System.Timers.Timer { Interval = 5, AutoReset = true };
gifTimer.Elapsed += GifTimer_Elapsed;

// Elapsed：Stopwatch 累积，达到帧间隔才推进 1 帧
private void GifTimer_Elapsed(object sender, System.Timers.ElapsedEventArgs e)
{
    gifAccumMs += gifSw.Elapsed.TotalMilliseconds;
    gifSw.Restart();
    if (gifAccumMs < gifFrameIntervalMs) return;   // 未到帧间隔
    gifAccumMs = 0;
    // BeginInvoke 回 UI 线程
    gifFrameIndex = (gifFrameIndex + 1) % gifFrameCount;  // 每次只 +1，不跳帧
    RenderFrame();
}
```

**设计要点**：Timer 只做 5ms 高频"到点检查"，实际帧推进由 Stopwatch 累积时间决定——帧率精确且不受 Timer 抖动影响。

### 2.5 档位 → 帧率映射（`GetGifFrameIntervalMs`）

```csharp
/// <summary>档位 → 目标帧间隔（毫秒）。gifStep：1=30fps / 2=100fps / 3=240fps。</summary>
private double GetGifFrameIntervalMs()
{
    switch (gifStep)
    {
        case 3:  return 1000.0 / 240;   // 240fps（高速）
        case 2:  return 1000.0 / 100;   // 100fps（中速）
        default: return 1000.0 / 30;    // 30fps（低速）
    }
}
```

| gifStep | 帧率 | 帧间隔 |
|---|---|---|
| 1（低速） | 30fps | 33.3ms |
| 2（中速） | 100fps | 10ms |
| 3（高速） | 240fps | 4.17ms |

## 三、档位判定稳定性修复

### 3.1 笔误修正

用户调试时误写为下载速度×2：

```csharp
long netPer_Sand_AND_Rec = netRecvPerSec + netRecvPerSec;  // 笔误：下载×2
```

变量名 `Sand_AND_Rec`（Send AND Rec）表明意图是「上传+下载」总速率，修正为：

```csharp
long totalRate = netSendPerSec + netRecvPerSec;   // 上传 + 下载总速率
```

### 3.2 EMA 平滑（削弱瞬时波动）

`updateTimer` 每秒采样一次，取的是**瞬时速率**，波动大。新增 `smoothedTotalRate` 字段做指数移动平均：

```csharp
private double smoothedTotalRate = 0;   // 平滑后的总速率

// 每采样周期：
smoothedTotalRate = smoothedTotalRate <= 0
    ? totalRate
    : smoothedTotalRate * 0.6 + totalRate * 0.4;   // α=0.4
```

### 3.3 滞回判定（避免阈值附近抖动）

升档/降档用不同阈值，中间留滞回带：

```csharp
int newStep = gifStep;   // 默认保持当前档位
switch (gifStep)
{
    case 1:   // 档1 → 档2：需 > 1.2 MB/s
        if (rate >= OneMB * 1.2) newStep = 2;
        break;
    case 2:   // 档2 → 档3：需 > 12 MB/s；档2 → 档1：需 < 0.8 MB/s
        if      (rate >= OneMB * 12)  newStep = 3;
        else if (rate <  OneMB * 0.8) newStep = 1;
        break;
    case 3:   // 档3 → 档2：需 < 8 MB/s
        if (rate < OneMB * 8) newStep = 2;
        break;
}
```

| 状态转移 | 阈值 | 滞回带 |
|---|---|---|
| 档1 → 档2 | > 1.2 MB/s | ±0.2 MB |
| 档2 → 档1 | < 0.8 MB/s | |
| 档2 → 档3 | > 12 MB/s | ±2 MB |
| 档3 → 档2 | < 8 MB/s | |

**效果**：速率在 1MB/s（或 10MB/s）附近小幅波动时，档位稳定不跳；必须真正跨过滞回带才切换。档位变化时才更新 `gifFrameIntervalMs`，避免每秒反复重设。

## 五、注意事项

1. **`timeBeginPeriod(1)` 影响全局**：它会提升**整个进程**的系统定时器分辨率，可能略微增加系统功耗/耗电。已通过 `FormClosing` 的 `timeEndPeriod(1)` 成对还原，但若进程异常终止（崩溃），分辨率不会自动还原（系统会在进程退出时自动恢复）。
2. **高帧率的实际开销**：240fps 意味着每秒 240 次 `BeginInvoke` + `RenderFrame`（位图合成 + `UpdateLayeredWindow`）。单次开销 <1ms，但若未来 GIF 尺寸/复杂度增大，需关注 UI 线程压力。
3. **帧率值的物理意义**：帧率决定「47 帧循环一圈的快慢」——30fps 一圈 ≈ 1.57s，100fps ≈ 0.47s，240fps ≈ 0.20s。240fps 已远超流畅阈值，实际观感是"极快转圈"。
